# VERSIONING.md
Requirement Knowledge Model Version Control — Version 1.0

---

## Objective
Every project maintains complete requirement history. No information is overwritten.

---

## Version Lifecycle

```
Draft → AI Generated → Human Review → Approved → Published → Archived
```

---

## Rules
- One Active Version.
- Unlimited Historical Versions.
- Previous versions immutable.
- Approval required.

---

## Version Numbering

| Change Type | Example | Trigger |
|-------------|---------|--------|
| Major | 1.0 → 2.0 | Business Requirement Changed |
| Minor | 1.0 → 1.1 | Clarification Added |
| Patch | 1.0 → 1.0.1 | Typographical Correction |

---

## Audit Trail

Every change stores: Who, When, Why, Previous Value, New Value, Approval, Timestamp

---

## Version Comparison

Users can compare:
- Requirement Changes
- Business Changes
- Risk Changes
- Assumption Changes
- Scope Changes
- Clarification Changes
- AI Reasoning Changes
