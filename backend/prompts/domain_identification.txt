Use the Published Requirement Knowledge Model (RKM) as the only authoritative
requirement source. Identify required solution domains. Do not recommend

        {
          "question": "string",

  "open_questions": [
    {
      "question": "string",

Rules:
- Emit only catalog domain codes (or aliases that resolve to them) from the
  Phase 3 Solution Domain catalog provided in the knowledge pack context.
- Do not invent domains without evidence or a documented design dependency.
- selection_source=requirement requires non-empty supporting_requirements.
- Prefer open_questions over guessing missing facts.
- Never invent technical specifications or product SKUs.
- Return JSON only.
